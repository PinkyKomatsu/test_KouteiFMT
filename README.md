# 医事会計システム更新 工程報告書作成アプリ

報告のトピックと要点メモを入力すると、過去の報告書の書き方にならった文面を**日本語と英語の両方で**作り、社内の Excel フォーマットの正しいセルに記入する Windows 用アプリです。

- **完全オフライン**：実行中は一切通信しません。英訳は PC の中で動く機械翻訳（CTranslate2 + opus-mt-ja-en）で行います。
- **フォーマットを決め打ちしない**：Excel フォーマットを取り込んで解析し、記入欄を自動で見つけます。迷う欄はプレビュー上でクリックして指定できます。
- **書式を崩さない**：罫線・結合セル・画像・図形・印刷設定・マクロはそのまま残り、値だけが書き込まれます。
- **日英を別々にコピー**：欄ごと、または全欄まとめて、日本語と英語をそれぞれコピーできます。

## 1. 使い方（利用者向け）

### 起動

`MedAcctReport` フォルダの中の **`MedAcctReport.exe`** をダブルクリックします。Python のインストールは不要です。

- 配布・移動するときは、**`MedAcctReport` フォルダごと**コピーしてください（`MedAcctReport.exe`・`_internal`・`models`・`data`）。
- 画面右下に「翻訳モデル：あり（オフライン）」と出ていれば、英訳が使えます。「なし」の場合は簡易訳（用語集だけの置き換え）になります。
- 初回に「Windows によって PC が保護されました」と表示されたら、［詳細情報］→［実行］を選びます（署名のない exe のため）。

### 最初の準備（1 回だけ）

**① フォーマットを取り込む（「フォーマット設定」タブ）**

1. ［Excelフォーマットを取り込む］で、工程報告のフォーマット（`.xlsx` / `.xlsm`）を選び、名前を付けます。
2. 左のプレビューに解析結果が表示されます。

   | 表示 | 意味 |
   | --- | --- |
   | 青 | ラベル |
   | 黄（［欄名］） | 記入欄 |
   | 紫 | 英語欄（例：Summary (EN)） |
   | オレンジの枠と「？」 | **要確認**（確信度が低い・右と下の両方に候補がある・枠のない欄・記入先が見つからない） |

3. 要確認の欄や違っている欄を直します。
   - 右の一覧で、欄名・種別・言語（日本語／英語／日英併記）・セル・使用を編集できます。
   - **記入先を変える**：一覧で欄を選び、プレビューでセルをクリック（表の行範囲はドラッグ）してから［この欄を記入先にする］。
   - **欄を足す**：プレビューでセルを選んで［記入欄として追加］（ラベルは左 → 上の順に自動で探します）。
   - **欄を外す**：プレビューでセルを選んで［記入欄から外す］。
4. ［定義を保存］を押します。要確認の欄が残っている場合は確認が出ます。

**② 過去の報告書を取り込む（「過去事例」タブ）**

- ［ファイルを追加］または［フォルダを追加］（サブフォルダも含む）で取り込みます。`~$` で始まる一時ファイルと `.xls` は取り込みません。
- 旧版のフォーマットで行がずれていても、ラベルを手がかりに正しく読み取ります。
- 英語欄がある報告書は、日英の対訳として保存され、英訳のときに優先して使われます（翻訳メモリ）。
- **個人情報**（患者 ID・氏名らしき文字列・生年月日・電話番号）が見つかると、［伏せ字にして取り込む］か［この報告書を取り込まない］かを選ぶ画面が出ます。
- フォーマットの定義を変えたときは［再読込］で読み直します。

**③ 設定（「設定」タブ）**

報告者・部署・日付書式・工程の候補・流用のオン／オフ・出力先・ファイル名パターン・用語集・翻訳モデルの場所を設定します。［動作確認］で翻訳モデルが使えるか確かめられます。

### 報告書を作る（「報告書作成」タブ）

1. 左側で、フォーマット・**トピック**（必須）・**工程**・**進捗**（予定どおり／遅延／完了／中止）・**要点メモ**を入力します。
2. ［類似事例を検索］で、内容の近い過去の報告書が類似度の高い順に並びます（同じ工程の事例は加点）。☑ の付いた上位 3 件から書き方を学びます。
3. ［文面を生成］を押すと、中央に欄ごとのカードができます。左が日本語、右が英語です（英訳は裏で行うので画面は固まりません）。

   | 背景色 | 意味 |
   | --- | --- |
   | 黄 | 過去事例の文面を流用（**要確認**。件名と日付は置き換え済み） |
   | オレンジ | 要確認（数値・日付の不一致、簡易訳など） |
   | 水色 | 機械翻訳 |
   | 緑 | 自動入力・定型文・翻訳メモリ |
   | 白 | メモから作った欄、または手で編集した欄 |

   各カードの下に判定の根拠（メモを整形／事例を流用／機械翻訳／簡易訳 など）が表示されます。日本語を直したら、［英訳を更新］でその欄だけ訳し直せます。
4. 右側の**記入後のプレビュー**で、Excel にどう入るかを確認します。
   - 「英語版で表示」で、英語だけを記入した場合の見た目に切り替わります。
   - プレビューのセルをクリックすると、対応するカードに移動します。
   - 記入先が決まっていない欄は、カードの［プレビューで記入先を指定］を押してから、プレビューのセルをクリックして指定できます。
5. **コピー**：欄ごとの［日本語をコピー］［英語をコピー］、または下の［日本語を全欄コピー］［英語を全欄コピー］。全欄コピーは次の形式になります。

   ```
   【件名】移行リハーサル（第2回）の結果報告

   【報告内容】
   お疲れ様です。
   ……
   ```
   英語は `[Subject] Migration rehearsal (2nd round) Results Report` の形式です。
6. **出力**：［Excelに出力］で保存します。ファイル名は `{date}_{phase}_{topic}.xlsx`（例：`20260927_移行リハーサル_移行リハーサル（第2回）の結果報告.xlsx`）です。
   - 日本語欄には日本語、英語欄（Summary (EN) など）には英語が入ります。英語欄がないフォーマットでは日本語だけが入ります。
   - ［英語版を別ブックで出力］で、同じフォーマットに英語だけを記入したファイル（末尾 `_EN`）も作れます。
   - 「出力後に開く」「過去事例に登録」は出力のたびに選べます。

## 2. 要点メモの書き方

メモは **1 行に 1 項目** 書きます。

| 書き方 | 入る欄 |
| --- | --- |
| `課題：点数マスタの差分が未確認` | 「課題」欄（その行だけ） |
| `【今後の予定】` だけの行 | 以降の行はすべて「今後の予定」欄 |
| `【背景】` だけの行（報告内容の見出しと同じ名前） | 以降の行は、報告内容のその見出しの下 |
| `件名：〇〇` | 件名を、トピックの代わりにこの内容にする |
| `内容｜担当｜期限｜状態` | 表の 1 行（No は自動で連番） |
| 欄名のない普通の行 | 過去の記載との類似度と役割（依頼／予定／課題／実績）から自動で振り分け |

**例**

```
9/26に移行リハーサル（第2回）を実施した
データ移行は計画の95%まで完了した
レセプトの点検で3件のエラーが発生した
課題：点数マスタの差分が未確認
【今後の予定】
10/3までにエラーの原因を調査する
10/10に本番移行の稼働判定会議を行う
エラー原因の調査｜山田｜10/3｜対応中
```

過去の報告書が「お疲れ様です。」で始まり、【背景】【状況】【対応】の見出し・「・」の箇条書き・です・ます調・「以上、ご報告いたします。」で書かれていれば、生成される文面もその形にそろいます。

```
お疲れ様です。
【背景】
・9/26に移行リハーサル（第2回）を実施しました。
【状況】
・データ移行は計画の95%まで完了しました。
・レセプトの点検で3件のエラーが発生しました。
【対応】
・特になし
以上、ご報告いたします。
```

英語（Summary (EN) 欄とコピー用）：

```
Please find my report below.
[Background]
・We ran migration rehearsal (2nd round) for 9/26.
[Status]
・Data transfer has been completed up to 95 percent of the plan.
・3 errors occurred during the medical claim (receipt) inspection.
[Actions]
・None
That concludes my report.
```

## 3. データの保存場所

exe と同じ階層に保存します。書き込めない場所に置いた場合は `%LOCALAPPDATA%\MedAcctReport\` を使います。

```
MedAcctReport/
  MedAcctReport.exe
  _internal/                         実行に必要なライブラリ
  models/ja-en/                      翻訳モデル（CTranslate2 int8、約 80MB）
  data/
    glossary.csv                     医事会計の用語集（日本語,英語）。設定画面から編集できます
    settings.json                    設定
    formats/<名前>/definition.json   フォーマット定義
    formats/<名前>/template.xlsx     取り込んだ原本のコピー
    formats/<名前>/cases.json        過去事例（伏せ字済み）と対訳
  log/app.log                        エラーの記録
```

## 4. 開発・ビルド（開発者向け）

### 必要なもの

- Windows 10 / 11
- Python **3.11**（[uv](https://docs.astral.sh/uv/) があれば `uv python install 3.11` で入ります）
- ビルド時・モデル準備時のみインターネット接続。できあがった exe は通信しません。

### ① 翻訳モデルの準備（開発 PC で 1 回だけ）

Helsinki-NLP/opus-mt-ja-en をダウンロードし、CTranslate2 の int8 形式に変換して `models/ja-en/` に保存します。torch と transformers はこの変換のときだけ使い、別の仮想環境に入れます。

```bat
cd report_app
uv venv --python 3.11 .venv-dev
uv pip install --python .venv-dev\Scripts\python.exe --index-url https://download.pytorch.org/whl/cpu --extra-index-url https://pypi.org/simple --index-strategy unsafe-best-match torch
uv pip install --python .venv-dev\Scripts\python.exe -r requirements-dev.txt
.venv-dev\Scripts\python tools\convert_model.py
```

`models/` は Git では管理しません（`.gitignore` 済み）。配布物には `build.bat` が同梱します。

### ② ビルド

```bat
build.bat
```

次を順に行います。どこかで失敗すると止まります。

1. `.venv`（Python 3.11）を作成
2. `requirements.txt` をインストール
3. `pytest` を実行
4. PyInstaller（`MedAcctReport.spec`：onedir・`--windowed`）で `dist\MedAcctReport\` を作成
5. `models\` と `data\glossary.csv` を `dist\MedAcctReport\` にコピー

> `build.bat` は **UTF-8・CRLF 改行** で保存してください。LF 改行だと cmd が日本語の行を正しく読めません。

### ③ テスト

```bat
.venv\Scripts\python -m pytest tests -v
```

テスト中は `socket` をモンキーパッチで禁止しており、通信なしで一連の処理が通ることも確認しています。

| ファイル | 内容 |
| --- | --- |
| `test_writer.py` | 書き込みエンジン：パーツ・画像・結合・印刷設定が同じ、指定したセルだけ変わる（セル単位の差分）、折り返しスタイルの複製、calcChain の削除、行・セルの挿入順、.xls の拒否、**Excel で開いて修復が出ない**（Excel がある場合、COM で確認） |
| `test_analyzer.py` | 記入欄の検出、上長コメント＝記入しない、Summary (EN)＝英語欄で報告内容と対、タイトル下の空行は欄にならない、曖昧な配置は要確認、日英ラベル・記入先なし・枠なし欄 |
| `test_cases.py` | 取り込み、行ずれ版をラベル基準で読める、個人情報（患者ID 1234567）の検出・伏せ字・中止、対訳の抽出、類似検索の 1 位、同じ工程の加点 |
| `test_generate.py` | 日本語が事例の見出し・箇条書き・文末・結び文にそろう、欄名指定、表、流用、Excel のセル・英語版、コピー用文字列、ファイル名 |
| `test_translate.py` | 英語欄がすべて埋まる、用語集（レセプト → medical claim）、日付・数値の一致、翻訳メモリ優先、日本語フォルダのモデル、**モデルなしでも生成が完了し「要確認（簡易訳）」になる**、10 秒以内、通信系モジュールを使っていない |

サンプルだけを作る：`.venv\Scripts\python tests\make_samples.py [出力フォルダ]`

### ④ 自己診断（exe の動作確認）

別の PC にコピーした exe で、次の 2 種類を実行できます。どちらも socket を禁止した状態で動きます。

```bat
rem 画面なしで「フォーマット取り込み → 事例取り込み → 生成 → プレビュー → コピー → 出力」
MedAcctReport.exe --selftest C:\temp\diag --format format.xlsx --reports 過去報告書のフォルダ

rem 実際の画面を自動で操作して同じ流れを確認し、各画面の画像を保存
MedAcctReport.exe --gui-selftest C:\temp\diag_gui --format format.xlsx --reports 過去報告書のフォルダ
```

結果は `selftest.json` / `gui_selftest.json` に書かれます。自己診断のデータは出力先の中に作るので、配布フォルダの `data\` は変わりません。

## 5. 前提（仕様上の仮定）

実装にあたって、次のように判断しました。

| # | 項目 | 判断 |
| --- | --- | --- |
| 1 | 場所 | 仕様例の `medacct_report/` ではなく、指示どおり既存の `report_app/` を作り替えました。以前の tkinter 版は置き換えています。 |
| 2 | Python | 開発 PC の既定は 3.14 でしたが、仕様どおり 3.11（3.11.16、uv で導入）で開発・ビルドしています。 |
| 3 | 用語の保護記号 | 仕様例の「⟦T1⟧」は opus-mt の語彙にない文字で、訳文で壊れることを確認しました。訳文にそのまま残る英数字の `T1`・`T2` を使っています。隣り合う用語はまとめて 1 つの記号にします。 |
| 4 | 回数・数字 | 「第2回」も用語と同じく保護し、`2nd round` として戻します。機械翻訳が「3件」を “Three” と言い換えた場合は数字に戻し、そのうえで数値・日付の一致を検証します。 |
| 5 | 英語サマリ欄 | 「Summary (EN)」のような英語の本文欄は、メインの本文欄（報告内容）と対にし、その英訳を記入します。 |
| 6 | 人名 | 報告者・担当者の名前は翻訳しません（そのまま）。用語集に「山田 太郎,Taro Yamada」のように登録すると、それを使います。 |
| 7 | 表の英訳 | 表は「アクション」「状態」を訳し、No・担当・期限はそのままにします。 |
| 8 | 表の流用 | メモに表の行がないとき、表は流用しません（古い期限や担当が残ると紛らわしいため）。本文系の欄は仕様どおり流用します。 |
| 9 | 記入先なしの欄 | 「日付」「件名」などの種別キーワードを含む 12 字以下のラベルで、記入先が見つからないものだけを「記入先が未確定」の欄にします（タイトルなどは対象外）。 |
| 10 | 個人情報 | 氏名は「氏名：」「患者名：」の後と「〇〇様」の形だけを対象にします（社内の担当者名を誤って伏せないため）。伏せ字は文字数を保った「●」です。出力した報告書を事例に登録するときは、確認なしで伏せ字にします。 |
| 11 | コピーの形式 | 日本語は「【欄名】本文」（複数行なら欄名の後で改行）、英語は「[Name] text」、表は「【No／アクション／…】」の見出しの下に 1 行 1 件で、欄の間は空行です。 |
| 12 | 日付書式 | 日本語は「自動（過去事例に合わせる）／yyyy/MM/dd／yyyy年M月d日／yyyy/M/d」、英語は「MMM d, yyyy（既定）／MMMM d, yyyy／yyyy-MM-dd」から選べます。 |
| 13 | 追加したファイル | UI から切り離してテストするため `app/report.py` を、画面で共有する状態・非同期処理のため `app/ui/common.py` を、取り込みと個人情報のテストのため `tests/test_cases.py` を、仕様の構成に加えました。 |
| 14 | 通信ゼロの確認 | テストと自己診断では socket を禁止して一連の処理が通ることを確認しています。開発時の確認では PC のネットワークを物理的には切っていません。 |

## 6. 制限事項・困ったとき

| 症状・制限 | 説明・対処 |
| --- | --- |
| 起動時に「Failed to load Python DLL …\build\MedAcctReport\_internal\python311.dll」と出る | `build\` フォルダ（PyInstaller の作業用）の exe を起動しています。**`dist\MedAcctReport\MedAcctReport.exe`** を起動してください。`build.bat` はビルド後に `build\` を削除します。 |
| 英訳の質 | opus-mt は小さな汎用モデルのため、言い回しが不自然なことがあります（例：“Research for Error Causes”）。用語集と翻訳メモリで改善できます。上長に出す前に英語欄を確認してください。 |
| 英語欄がオレンジ | 数値・日付・英数字の語が訳文と一致しない、または用語が訳文に残らなかった欄です。カードの根拠を見て直してください。 |
| 「翻訳モデル：なし」と出る | `models\ja-en\model.bin` があるか確認してください。設定画面で別の場所を指定し、［動作確認］で確かめられます。モデルがなくても簡易訳で動きます。 |
