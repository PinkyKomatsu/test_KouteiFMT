# Excel報告書作成アシスタント

トピックと要点メモを入力するだけで、過去の報告書の書き方にならった下書きを作り、社内の Excel フォーマットどおりに記入した報告書を出力する Windows 用アプリです。

- **完全オフライン**：通信・クラウド API・生成 AI は使いません。文章はルールベースで作ります。
- **フォーマットを決め打ちしない**：取り込んだ Excel を解析して、記入欄を自動で見つけます。
- **書式を崩さない**：罫線・結合セル・画像・図形・印刷設定・マクロはそのまま残り、値だけが書き込まれます。
- **単体の exe**：Python をインストールしていない PC でも、exe と `data` フォルダをコピーするだけで動きます。

## 1. 使い方（exe を使う人向け）

### 起動

`ReportAssistant.exe` をダブルクリックします。配布するときは、`ReportAssistant.exe` と `data` フォルダを同じ場所にまとめてコピーしてください。

> 初回起動時に「Windows によって PC が保護されました」と表示された場合は、［詳細情報］→［実行］を選びます（署名のない exe のため表示されます）。
> 単体 exe は起動時に中身を展開するため、起動まで数秒かかります。

### 最初の準備（1 回だけ）

**① フォーマットを取り込む**（「フォーマット設定」タブ）

1. ［Excelフォーマットを取り込む］で、社内の報告書フォーマット（`.xlsx` / `.xlsm`）を選びます。
2. フォーマットの名前を入力すると、自動で解析されます。
3. 左のプレビューで確認します。**青＝ラベル**、**黄＝記入欄**（欄名付き）で表示されます。
4. 違っているところがあれば右の一覧で直し、［定義を保存］を押します。
   - 欄名・種別・セル・使用（記入するかどうか）を編集できます。
   - 足りない欄は、プレビューでセルをクリックして［選択セルを記入欄に追加］を押します。ラベルは左 → 上の順に自動で探します。
   - 不要な欄は［削除］、順番は［上へ］［下へ］で変えます。

**② 過去の報告書を取り込む**（「過去事例」タブ）

- ［ファイルを追加］または［フォルダを追加］で、過去の報告書を取り込みます。フォルダはサブフォルダも含めて探します。
- 取り込みの結果と警告は、下の「取り込みログ」に表示されます。
- フォーマットの定義を変えたときは［再読込］で、取り込み元のファイルから読み直します。

**③ 自分の情報を設定する**（「設定」タブ）

- 報告者・部署を入れておくと、毎回自動で記入されます（空欄なら過去事例で最も多い値を使います）。

### 報告書を作る（「報告書作成」タブ）

1. **トピック**（件名になります）と**要点メモ**を入力します。
2. ［類似事例を検索］を押すと、内容の近い過去の報告書が類似度の高い順に並びます。
   - ☑ の付いた上位 3 件から、書き方（箇条書きの記号・文末・見出し・定型文）を学習します。クリックで ☑ を切り替えられます。
   - 事例を選ぶと、下に内容のプレビューが表示されます。
3. ［下書きを作成］を押すと、右側に欄ごとの下書きが入ります。自由に編集できます。

   | 背景色 | 意味 |
   | --- | --- |
   | 黄 | 過去事例の文面を流用した欄（**要確認**） |
   | 緑 | 自動で入れた欄（日付・報告者・部署など） |
   | 白 | メモから作った欄、または手で編集した欄 |

   各欄の下には、どう作ったか（根拠）が表示されます。
4. ［Excelに出力］を押して保存先を選びます。
   - ファイル名は `20260926_トピック.xlsx` のように付きます（設定で変更できます）。
   - 「出力後に開く」「過去事例に登録」は、出力のたびに選べます。

## 2. 要点メモの書き方

メモは **1 行に 1 項目** 書きます。

| 書き方 | 入る欄 |
| --- | --- |
| `課題：監視の設定が不十分` | 「課題」欄（その行だけ） |
| `【今後の対応】` だけの行 | 以降の行はすべて「今後の対応」欄 |
| `【背景】` だけの行（報告内容の見出しと同じ名前） | 以降の行は、メイン本文欄のその見出しの下 |
| `件名：〇〇の件` | 件名をトピックの代わりにこの内容にする（日付・報告者・部署も同様） |
| `内容｜担当｜期限｜状態` | 表の 1 行（No は自動で連番） |
| 欄名のない普通の行 | 内容から最も合う欄を自動で判断 |

欄名のない行は、「その欄の過去の記載との似ている度合い」と「役割（依頼・予定・課題・実績）のキーワード」から入れる欄を決めます。どこにも当てはまらない行は、メイン本文欄（ラベルに「内容」「概要」「報告」を含む欄、なければいちばん大きい欄）に入ります。

**例**

```
9/25 夕方にメールサーバーで障害が発生した
原因はディスク容量の不足
不要なログを削除して復旧済み
課題：容量の監視設定が不十分
【今後の対応】
容量監視のアラートを追加する
10/3までに運用手順書を更新する
監視設定の見直し｜山田｜10/3｜対応中
```

過去事例が「・」の箇条書き・です・ます調・見出し【背景】【状況】【対応】・結び「以上、ご報告いたします。」で書かれていれば、下書きもその形にそろいます。

```
お疲れ様です。
【背景】
・9/25 夕方にメールサーバーで障害が発生しました。
【状況】
・原因はディスク容量の不足です。
・不要なログを削除して復旧済みです。
【対応】
・特になし
以上、ご報告いたします。
```

## 3. しくみ

### フォーマット解析

結合セルは左上のセルにまとめて扱い、次の順で記入欄を推定します。

1. **表**：同じ行に 3 つ以上並んだラベルの下が空欄なら表とみなし、罫線付きの空欄が続く行数だけ記入欄にします。
2. **同じセル内**：「件名：〇〇」の形なら、同じセルに「件名：」を付けて書きます。
3. **右・下の空欄**：まず全ラベルの「右」を決め、その後で残りに「下」を割り当てます。
   - 罫線も結合もない空白は余白とみなし、記入欄にしません。
   - シート幅の 60% 以上ある見出しは「下」を採ります。
   - 右が単独セルで、下が 2 倍以上大きな結合欄なら「下」を採ります。

欄の種別はラベルのキーワードで決めます。

| 種別 | キーワード |
| --- | --- |
| 日付 | 日付・報告日・作成日 |
| 件名 | 件名・表題・テーマ |
| 報告者 | 報告者・担当者・氏名 |
| 部署 | 部署・所属 |
| 記入しない | 承認・検印・上長・宛先（最初から「使用」オフ） |
| 本文 | 上記以外 |

### 過去事例の読み取り

値は**ラベルを基準に**探します。旧版のフォーマットで行がずれていても、同じラベル文字列を見つけて、そこから同じ位置のセルを読みます。ラベルが見つからないときだけセル番地で読み、警告を出します。

### 類似検索

文字の 2-gram・3-gram による TF-IDF とコサイン類似度で比べます。件名は重みを 2 倍にし、検索語は「トピック＋メモ」です。

### 下書きの生成

上位 3 件の参考事例から、欄ごとに次を学習してメモを整えます。

- 箇条書きの記号（・ ■ ① 1. (1) など）
- 文末（です・ます調／だ・である調／体言止め）と句点の有無
- 見出しの構成（半数以上の事例にあるもの）
- 冒頭文・結び文（半数以上の事例で同じ位置にあるもの）

文末は変換表でそろえます（した → しました、している → しています、できない → できません など）。です・ます調の事例に対しては、体言止めのメモに「です」を補います。

メモのない本文欄は、最上位の事例の文面を流用し、旧件名をトピックに、日付を本日に置き換えます（黄色で表示）。流用は設定でオフにできます。

### Excel への書き込み

openpyxl で保存すると画像や図形が失われるため、使いません。xlsx を ZIP として開き、対象シートの XML だけを lxml で書き換え、それ以外のパーツは中身をそのまま複製します。

- 既存セルのスタイル（罫線・フォントなど）はそのまま残します。
- 複数行の文章を書くセルに折り返しの設定がなければ、そのスタイルを複製して折り返しを付けたものを割り当てます（元のスタイルは変えません）。
- 数式のセルを上書きした場合は、Excel の計算チェーン（calcChain）を削除します。Excel が開くときに作り直します。

## 4. データの保存場所

exe と同じフォルダの `data` に保存します。書き込めない場所（`C:\Program Files` など）に置いた場合は、`%LOCALAPPDATA%\ReportAssistant\data` を使います。実際の保存先は「設定」タブの下に表示されます。

```
data/
  settings.json                    設定
  formats/<フォーマット名>/
    format.json                    フォーマット定義（記入欄の一覧）
    template.xlsx                  取り込んだ原本のコピー（.xlsm ならそのまま）
    cases.json                     過去事例
```

- 別の PC に移すときは、`ReportAssistant.exe` と `data` フォルダをまとめてコピーします。
- バックアップは `data` フォルダをコピーするだけです。

### 設定項目（`settings.json`）

| 項目 | 内容 | 既定値 |
| --- | --- | --- |
| 報告者 / 部署 | 空欄なら過去事例で最も多い値 | 空欄 |
| 日付書式 | 自動（過去事例に合わせる）／ 2026/09/26 ／ 2026/9/26 ／ 2026年9月26日 ／ 2026年9月26日（土）／ 2026-09-26 | 自動 |
| 流用 | メモのない欄に過去事例の文面を流用する | オン |
| 色分け | 流用・自動入力の欄を色分けする | オン |
| 過去事例に登録 | 出力した報告書を過去事例に登録する（既定値） | オン |
| 出力後に開く | 出力後に Excel で開く（既定値） | オン |
| 出力先フォルダ | 空欄ならドキュメント | 空欄 |
| ファイル名パターン | `{date}`（例 20260926）・`{topic}`・`{reporter}` が使えます | `{date}_{topic}` |

## 5. 開発・ビルド

### 必要なもの

- Windows 10 / 11
- Python 3.11 以降（3.14.7 で動作確認済み）。インストール時に「Add python.exe to PATH」をオンにします。
- ビルド時のみインターネット接続（ライブラリのダウンロードのため）。できあがった exe は通信しません。

使うライブラリは `openpyxl`（読み取り専用）・`lxml`・標準ライブラリの `tkinter` だけです（ビルドに `pyinstaller`）。

### exe を作る

```bat
cd C:\work\VSCode\report_app
build.bat
```

`build.bat` は次を順に行います。

1. 仮想環境 `.venv` を作成（すでにあれば省略）
2. `requirements.txt` のライブラリをインストール
3. PyInstaller（`--onefile --windowed`）で `dist\ReportAssistant.exe` を作成し、`dist\data` を用意

> `build.bat` は **UTF-8・CRLF 改行** で保存してください。LF 改行だと、cmd が日本語の行を正しく読めずに失敗します。

### exe を作らずに動かす

```bat
.venv\Scripts\python main.py
```

開発時のデータはプロジェクト直下の `data` に保存されます。環境変数 `REPORT_APP_DATA` を指定すると、保存先を変えられます。

### セルフテスト

GUI を出さずに、登録済みのフォーマットで「検索 → 下書き作成 → 出力」を一通り行い、結果を `<出力先>\selftest.json` に書きます。別の PC にコピーした exe の動作確認に使います。

```bat
ReportAssistant.exe --selftest C:\temp\selftest
```

## 6. テスト

```bat
.venv\Scripts\python -m unittest tests.test_flow -v
```

`tests/make_samples.py` が、架空のフォーマット（ロゴ画像・図形・数式・印刷設定入り）と過去報告書 5 件（うち 1 件は行が 1 行ずれた旧版）を一時フォルダに作り、次を確認します。

| テスト | 内容 |
| --- | --- |
| test_1 | 記入欄が正しく検出される。上長コメントは「記入しない」、タイトル下の空行は欄にならない |
| test_2 | 行がずれた過去報告書も、ラベル基準で正しく読める。`~$` の一時ファイルと `.xls` は除外される |
| test_3 | 類似検索で、内容の近い事例が 1 位になる |
| test_4 | 下書きが過去事例の見出し・箇条書き・文末・結びの定型文にそろう。メモのない欄は流用される |
| test_5 | 出力した Excel の結合セル数・画像・スタイル・印刷設定が原本と同じ。calcChain の削除、行・セルの挿入順、`.xls` の拒否 |
| test_6 | Excel で開いても修復メッセージが出ない（COM で確認。Excel がない環境ではスキップ） |
| test_7 | 通信系モジュールを使っていない。exe を `data` ごと別フォルダにコピーしてもセルフテストが通る（exe がない場合はスキップ） |

- サンプルだけを作る：`.venv\Scripts\python tests\make_samples.py [出力フォルダ]`（既定は `tests\samples`）
- テストで作ったファイルを残す：環境変数 `KEEP_TEST_FILES=1` を付けて実行すると、終了時に場所を表示します。

## 7. ファイル構成

```
report_app/
  main.py              エントリポイント（DPI 対応、--selftest）
  app/
    xlsx_writer.py     書式を壊さない書き込み（ZIP + lxml）
    analyzer.py        フォーマット解析・記入欄の推定
    cases.py           過去事例の抽出・類似検索
    textutil.py        日本語処理（正規化・n-gram・文末変換・箇条書き・日付）
    generator.py       ルールベースの下書き生成
    storage.py         JSON 保存（data/ または %LOCALAPPDATA%）
    gui.py             tkinter GUI
  tests/
    make_samples.py    テスト用のフォーマットと過去報告書を作る
    test_flow.py       一連の動作テスト
  build.bat            venv 作成 → pip install → PyInstaller
  requirements.txt     openpyxl, lxml, pyinstaller
```

## 8. 制限事項・困ったとき

| 症状・制限 | 説明・対処 |
| --- | --- |
| `.xls` を取り込めない | 旧形式には対応していません。Excel で開き「名前を付けて保存」で `.xlsx` にしてください |
| 出力時に「保存できませんでした」と出る | 同じ名前のファイルを Excel で開いていないか確認してください |
| 記入欄がうまく検出されない | 「フォーマット設定」タブで欄を修正・追加してください。罫線のない空欄は余白とみなされます |
| 過去事例の取り込みで警告が出る | ラベルが見つからずセル番地で読んだ欄です。フォーマットの版が大きく違う可能性があります |
| 表に過去の内容が流用されない | 表は古い期限や担当が残ると紛らわしいため、流用しません。メモに `内容｜担当｜期限｜状態` の形で書いてください |
| 表の行が足りない | 表の行数を超えたメモの行は記入されず、欄の根拠に表示されます |
| 共有数式のセルを上書きした | 同じ数式を共有していたセルは値だけになります（出力時に警告を表示） |
| exe がウイルス対策ソフトに止められる | PyInstaller で作った exe は誤検知されることがあります。社内の手順に従って許可してください |
